# TUI 优化评估与验收

本轮基于源码、运行时测试和 headless terminal 测试完成。未调用真实模型生成，也未以自动化测试代替真实终端的长期使用验证。

## 已完成

| 问题 | 改进 | 验收 |
| --- | --- | --- |
| 新建对话与清屏语义不统一 | `/new` 开新对话并保留旧输出；`/clear` 清屏并开新对话；Ctrl+L 只清屏且保留上下文、草稿与统计 | 旧会话可恢复；保存失败不清屏；运行中禁止操作；缩放和退出不重现已清除输出 |
| 首次 Agent 创建期间 Esc 无效，待发送消息仍可能发出 | 创建使用独立取消信号；丢弃取消的待发送消息并释放迟到的 Agent | 延迟创建后取消，无消息提交；随后可重新发起请求 |
| 模型、会话选择器仍显示聊天输入框，焦点不明确 | 所有选择器独占当前操作区域；退出后恢复原草稿 | 搜索和确认期间不显示聊天发送提示，退出后草稿可提交 |
| 列表缺少位置反馈，窄屏操作提示被截断 | 增加当前位置/总数，窄屏使用简短按键提示 | 长列表、搜索、键盘选择及终端尺寸检查 |
| 极小窗口裁掉审批操作 | 优先保留审批正文、分页与允许/拒绝/取消，空间不足时隐藏附加状态栏 | 16×5、24×7、40×10、80×24 下操作与翻页均可见 |
| 超长工具名和排队提示挤掉 Esc stop | 为停止操作预留宽度，极窄时优先显示停止操作 | 16、24、40 列下工具名超长仍能显示 Esc stop |
| 模型偏好写盘时仅显示笼统 Loading | 显示具体保存状态 | 不改变原有保存失败重试行为 |

已有的模型/思考深度持久化、实时状态栏预览、原子文件替换、流式内容提交去重、审批队列和失败恢复保留。

## 后续优先级

1. **多进程配置一致性**：目前单文件原子替换可避免半写文件，但多个进程同时读改写仍可能覆盖彼此的会话偏好。需要跨进程串行化或拆分每会话存储，并加入多进程争用测试。
2. **会话工作流**：每会话草稿、会话重命名、会话搜索与导出。先明确 Harness 的存储接口，避免 UI 自行维护第二份对话事实。
3. **可观测性**：重试次数、等待原因、压缩阶段、请求耗时。应消费 Harness 的正式事件，未知值保持未知，不用文本长度推算 token。
4. **长会话性能**：对 Transcript.frame 的历史展开、Markdown 重排和大段粘贴建立基准，再按测量结果做缓存及增量布局。
5. **真实环境回归**：在 macOS Terminal、iTerm2、tmux、SSH 下验证中文输入法、Unicode 宽度、粘贴、窗口缩放和退出恢复；补充真实 provider 的取消、断网与限流演练。

以上后续条目是评估发现的下一阶段工作，不代表本轮已实现。
